# 概念学习资料生成器（concept-study-guide）

## 一、这个 Skill 解决什么问题

我在自学时发现两个毛病：一是让 AI 解释一个概念，它给一大段文字，看着懂了，第二天全忘；二是资料里全是结论，没有我自己的判断，交作业或跟人讨论时说不出「我为什么这么理解」。

所以这个 Skill 的定位不是「让 AI 写一篇科普」，而是**产出一份能逼我动脑、并且事后能验证真伪的学习资料**。两条硬规矩：

1. **必须有个人解释**：每份资料里「我的理解」部分要用学习者自己的话写，不能是 AI 输出原文照搬。
2. **来源必须可核查**：每个关键论断都要挂一个能点开的公开链接，且链接必须由学习者自己访问确认过，禁止凭印象编造 URL。

---

## 二、适用场景

- 遇到一个陌生概念，想系统搞懂而不是只看个定义（如 Agent、上下文、Skill、RAG、KV Cache、注意力机制）。
- 学完一段内容后，想检验自己到底有没有真懂。
- 需要把零散的笔记整理成一份可复用的复习材料。
- 准备课程作业、分享或考试前梳理某个主题。

**不适用场景**：
- 只要一句话定义的查词（直接问就行，不必启动这个 Skill）。
- 需要最新实时数据的调研（本 Skill 强调可核查的静态来源，实时行情类请用搜索工具）。

---

## 三、输入信息

启动前收集。**不知道的可以填「未指定」，我会给默认值**，只有 `概念` 是必填。

| 输入项 | 必填 | 说明 / 默认值 |
|---|---|---|
| `概念` | 是 | 要学的概念名，如「大模型的上下文」 |
| `我的起点` | 否 | 已知道什么、在哪儿卡住。默认「零基础」 |
| `学习动机` | 否 | 为什么要学（作业 / 项目 / 好奇）。默认「建立基础认知」 |
| `深度` | 否 | `速览`(15 分钟) / `标准`(默认) / `深挖`(含原始论文与实现细节) |
| `输出格式` | 否 | `HTML`(默认，单文件、浅色主题) / `Markdown` |
| `输出路径` | 否 | 默认 `learning-materials/<概念英文名>.html` |

**最小可用输入**：`用 concept-study-guide 学一下 Skill 这个概念`。信息不足时不要用一堆问题打断，先按默认值产出第一版，再让学习者补充。

---

## 四、生成步骤

严格按顺序执行，前一步没完成不要跳到下一步。

### 步骤 1：确认输入
复述一遍「概念 + 起点 + 深度」，确认理解一致。若概念有歧义（如「上下文」可指对话历史、语境、context window），先明确本次取哪个含义。

### 步骤 2：检索并锁定来源（关键，不可跳过）
至少找 3 个来源，且满足：
- **优先一手来源**：官方工程博客、官方文档、原始论文、权威教材。
- **次选**：高质量技术博客、知名课程讲义（需标明是二手解读）。
- **避免**：无署名的内容农场、营销软文、无法追溯来源的转载。

对每个来源，记录：`标题 / URL / 作者或机构 / 发布时间 / 它支撑了资料里的哪句话`。
**先用 WebFetch 或 WebSearch 实际访问确认页面存在、内容对得上**，再写进资料。访问失败或内容不符的，直接丢弃，不许凭印象写 URL。

### 步骤 3：搭骨架
按第六节的输出结构逐节填充。先写「核心机制」，再写「应用场景」，最后写「易混淆点」——顺序不能反，因为边界问题必须建立在对机制的准确理解之上。

### 步骤 4：写「我的理解」
用自己的话重写，句式要求：**一个类比 + 一句大白话 + 一句「它其实不是什么」**。例：
> 类比：上下文就像 Agent 的「工作台」，不是它的「仓库」。
> 大白话：模型每一步能看到的全部信息，就是它这一刻的世界。
> 它其实不是：不是聊得越久模型就越懂你，堆太多反而会让它抓不住重点。

### 步骤 5：设计自测题
出 5 道题，覆盖：定义 1 题、机制 2 题、场景或边界 1 题、迁移应用 1 题。必须有**判分要点**（答到什么算对），不能只给答案。

### 步骤 6：自检
逐条过第七节的自检清单，**任何一条不通过就修改后重跑**，直到全通过。

### 步骤 7：交付并邀请修订
输出文件后，明确告诉学习者：「以下是 AI 初稿，请做三件事——① 点开每个链接确认；② 把『我的理解』改成你自己的话；③ 标记你不同意的判断。」并列出本次生成中最需要人工确认的 2-3 个点。

---

## 五、输出结构

每份学习资料固定十节，缺一节视为不合格：

1. **学习档案卡** — 概念 / 领域 / 我的起点 / 深度 / 预计耗时 / 生成日期
2. **一句话定义** — 30 字内，说人话
3. **学习目标** — 3 条，动词开头、可检验（如「能画出 X 的流程图」而非「了解 X」）
4. **核心问题** — 2-3 个驱动问题，资料读完应能回答
5. **核心机制 / 组成** — 拆成 3-5 个部分，配流程图或结构图（Mermaid 或 SVG）
6. **最小心智模型** — 一个类比，让外行也能听懂
7. **我的理解** — 类比 + 大白话 + 「它其实不是什么」（本 Skill 的强制项）
8. **具体应用场景** — 一个真实场景，写清楚「谁用、怎么用、为什么非它不可、效果怎么衡量」
9. **易混淆 & 使用边界** — 表格：混淆对象 / 表面相似点 / 本质区别 / 判断口诀；再列 2-4 条「什么情况下不该用它」
10. **自测题（5 题）** — 附判分要点，折叠显示答案
11. **可核查来源** — 表格：标题 / 链接 / 类型（一手/二手）/ 支撑了哪句话 / 我已核实（是/否）
12. **我的存疑点** — 至少 1 条，写下还没搞明白或不同意的判断

## 六、格式要求（HTML）

- 单文件、自包含，不引外部 CDN（离线也能打开）。
- **浅色主题**：白/浅灰底、深色文字，正文 15-16px，行高 1.7，正文宽度约 800px 居中。
- 顶部有目录锚点导航；小节之间留足留白。
- 表格有表头底色和边框；来源链接新窗口打开、带下划线。
- 自测题答案默认 `<details>` 折叠。
- 每份资料开头放一句话：「本资料由 AI 初稿 + 本人核查修订，核查记录见 README。」

---

## 七、自检清单（交付前逐条打勾）

**内容准确性**
- [ ] 每个关键论断都能追溯到第六节列出的某个来源，没有无来源的断言。
- [ ] 所有 URL 都是我实际访问过的，没有 404、没有凭印象编的链接。
- [ ] 一手来源 ≥ 1 个，总来源 ≥ 3 个。
- [ ] 数字、日期、版本号等硬事实与来源一致（不确定的宁可不写）。
- [ ] 没有把 AI 对话原文整段照搬进「我的理解」。

**结构完整性**
- [ ] 第五节的十几个小节全部存在，没有空缺。
- [ ] 有图（Mermaid/SVG/表格）呈现核心机制，不是纯文字。
- [ ] 自测题有判分要点，不是只有答案。
- [ ] 「我的存疑点」非空——一个概念如果学完没有疑问，通常说明没学透。

**可用性**
- [ ] 外行读完「最小心智模型」能大致明白这个概念在干嘛。
- [ ] 应用场景写了「为什么非它不可」，不是硬凑的例子。
- [ ] 边界部分明确列出了「什么情况下不该用」。
- [ ] HTML 能独立打开，无外部依赖报错。

**可复用性（本项针对 Skill 本身）**
- [ ] 换成任意一个陌生概念，本流程无需修改即可执行。
- [ ] 没有把只适用于某个具体概念的规则写进流程。

## 八、使用示例

**输入**：`用 concept-study-guide 学「大模型的上下文」，我是 AI 应用课的学生，已知道 prompt 是什么，标准深度。`

**输出**：`learning-materials/llm-context.html`，包含十节完整结构、一张上下文构成示意图、5 道自测题、3 个以上一手来源。

---

## 九、注意事项

- **不做资料伪造**：找不到可靠来源时，明确写「暂未找到可靠来源，此处为推测」，好过编一个链接。
- **不做过度简化**：机制部分可以通俗，但不能失真。通俗和准确冲突时，保留准确，另用类比补救。
- **保留个人声音**：资料是给学习者自己看的，鼓励在「我的理解」里写主观判断、写反对意见。
- **敏感信息**：永不把 API Key、密码、个人信息写进任何学习资料；仓库 `.gitignore` 已排除 `.env`、`*.key` 等。
- **迭代**：学习者在真实使用中发现问题后，回来改这个 SKILL.md，并在 README 记录版本变化。
